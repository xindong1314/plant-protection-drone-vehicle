# 项目模块台账

> 适用范围：`PlantProtectionDroneVehicle` 当前 `master` 代码。  
> 状态：维护中。  
> 最近核对：2026-08-23。
> 判定原则：以代码、数据库迁移和可访问页面为准；规划描述不等于已经实现。

本文记录各模块的实际落地状态、入口和主要缺口。整体分层与技术选型见 [architecture.md](architecture.md)，启动方式见 [deployment.md](deployment.md)，车云消息格式见 [protocol.md](protocol.md)。

## 状态定义

| 标记 | 含义 |
|---|---|
| ✅ 已完成 | 存在主要实现与可用入口，能够参与当前业务链路 |
| 🟡 部分完成 | 已有部分代码、接口或页面，但尚未形成完整产品闭环 |
| ⬜ 规划中 | 只有目录、说明或规划，尚无可运行实现 |

## 二、业务前端（PPDVweb）

页面路由统一经过 JWT 登录守卫，使用 `PPDVapi` 的 REST API，并通过 `/ws/telemetry` 接收实时事件。

| 模块 | 路由 | 状态 | 已实现能力 | 主要缺口 |
|---|---|---:|---|---|
| 登录与应用框架 | `/login` | ✅ | JWT 登录、按权限选择落地页、页面/操作级权限展示和可恢复的 403 页面 | 尚未建立前端权限矩阵自动化测试 |
| 监控总览 | `/dashboard` | ✅ | 设备总数/在线/作业/告警 KPI，状态与电量图表，事件与告警流 | 告警确认、通知闭环尚未实现 |
| 数字驾驶舱 | `/cockpit` | ✅ | 选车、实时状态、电量仪表、历史轨迹、远程控制指令 | 视频流、声光告警和驾驶安全联锁未实现 |
| 作业规划 | `/planning` | 🟡 | 选择持久化区域或手绘地块、绘制航线、参数配置和任务下发 | 航线和下发任务未持久化，未形成可查询的任务生命周期 |
| 区域管理 | `/area` | ✅ | 区域列表、GCJ-02 地块边界绘制/回显、信息维护和受保护删除 | 尚无地块版本、电子围栏和空间分析 |
| 区域档案 | `/archive` | ✅ | 区域风险、巡检、异常、点喷累计及最近业务动态 | 未展示完整图片和任务明细时间线 |

## 四、云平台后端（PPDVapi）

### 4.1 平台与设备链路

| 模块 | 包或入口 | 状态 | 主要能力 | 数据/依赖 |
|---|---|---:|---|---|
| 登录与会话 | `security/`、`system/controller/SysLoginController` | ✅ | Spring Security、JWT、Redis 会话、登录/登出、路由与权限信息 | Redis、MySQL |
| RBAC 系统管理 | `system/` | ✅ | 用户、角色、菜单、部门、岗位、字典、参数和个人中心 CRUD | MySQL `sys_*` 表 |
| 设备管理 | `device/` | ✅ | 台账、在线状态、一机一密、当前区域、密钥重置 | MySQL `device` 表 |
| 遥测接入与查询 | `telemetry/` | ✅ | 状态/作业遥测入库、快照更新、状态与环境历史查询 | TDengine、MySQL |
| WebSocket 推送 | `TelemetryWebSocketHandler` | ✅ | `/ws/telemetry?token=JWT` 实时广播状态、作业和告警事件 | JWT、WebSocket |
| MQTT 车云通信 | `mqtt/`、`protocol/` | ✅ | 上行订阅、下行发布、Topic 封装和消息信封 | EMQX |
| EMQX 认证授权 | `emqx/` | ✅ | HTTP 一机一密认证、设备 Topic 授权、服务账号放行 | EMQX HTTP 回调 |
| 远程指令 | `command/CommandController` | ✅ | START、PAUSE、RESUME、ESTOP、RTL 等指令发布 | MQTT `cmd/req` |
| 地图任务下发 | `command/TaskController` | 🟡 | 接收内联地块/航线参数并发布 `task/assign` | 尚无独立任务持久化和进度管理 API |

### 4.2 植保业务闭环

业务目标链路为：区域建档 → 巡检采集 → 识别结果 → 风险评估 → 点喷任务 → 喷后复查 → 档案与报表更新。

| 模块 | API 前缀 | 状态 | 已实现能力 | 主要缺口 |
|---|---|---:|---|---|
| 区域管理 | `/ppdv/area` | ✅ | 区域 CRUD、档案同步、关联数据删除保护、GCJ-02 边界校验与风险状态 | 暂无地块版本、电子围栏和空间分析 |
| 巡检管理 | `/ppdv/inspection` | ✅ | 巡检分页、启动/完成、图片登记与上传、识别结果写入及查询，并有业务页面 | 视觉识别模型不在本仓库内 |
| 文件存储 | `storage/FileStorageService` | 🟡 | 巡检图片本地安全存储与静态访问 | 尚未接入对象存储、病毒检测和生命周期管理 |
| 风险评价 | `/ppdv/risk`、`/ppdv/risk/config` | ✅ | 规则范围/阈值关系校验、区域风险计算与结果回写，并有配置页面 | 规则效果仍需业务数据验证 |
| 点喷任务 | `/ppdv/task/spray` | 🟡 | 高风险区域任务校验、在线设备分配、状态更新、执行并发布点喷指令 | 车端实际执行与可靠回执尚未落地 |
| 喷后复查 | `/ppdv/task/review` | 🟡 | 校验任务、区域和关联图片后创建复查记录，按任务或区域查询 | 自动判定模型尚未接入 |
| 区域档案 | `/ppdv/archive` | ✅ | 随区域自动建档、地图摘要、区域详情和独立业务页面 | 未提供完整业务明细时间线 |
| 汇总报表 | `/ppdv/report` | ✅ | 时间范围内的巡检、异常、点喷、复查和区域汇总，支持 CSV 导出 | 暂无定时报表 |

## 五、车载端（PPDVedge）

当前仅有 ROS2 规划目录和 README，没有可编译节点、launch 文件或硬件驱动，因此统一标记为规划中。

已在 Atlas 200I DK A2 上手工跑通 ROS2 Humble、N10P 激光雷达 `/scan`、Astra Pro Plus 深度相机和基于静态 TF 的 `slam_toolbox` 建图，实测记录见 [PPDVedge/docs/hardware/](../PPDVedge/docs/hardware/README.md)。这些是环境与驱动验证，尚未形成仓库内的节点代码，模块状态保持不变。

| 模块 | 目录 | 状态 | 规划职责 |
|---|---|---:|---|
| 环境感知 | `perception/` | ⬜ | 传感器融合、障碍物与作物行识别 |
| 定位导航 | `navigation/` | ⬜ | RTK/SLAM、覆盖规划、局部避障和路径跟踪 |
| 运动控制 | `control/` | ⬜ | 底盘驱动、转向与速度闭环 |
| 喷洒控制 | `spray/` | ⬜ | 喷头、流量、压力和变量喷洒 |
| 安全防护 | `safety/` | ⬜ | 急停、电子围栏、碰撞保护和故障诊断 |
| 通信上报 | `comm/` | ⬜ | MQTT 收发、断网缓存与重连补传 |

## 七、现有自动化验证

后端当前有 53 个单元测试，分布在 7 个测试类：

- `ArchiveServiceTest`：档案批量聚合及并发更新锁定。
- `AreaServiceTest`：区域生命周期、字段与几何校验、关联数据删除保护。
- `InspectionServiceTest`：设备/区域/图片关系校验、识别结果持久化顺序和计数更新。
- `RiskConfigServiceTest`、`RiskEvaluationServiceTest`：配置范围、阈值关系、并发锁定及忽略结果过滤。
- `PlantProtectionServiceTest`：点喷状态流转、在线设备、复查关系和聚合列表。
- `FileStorageServiceTest`：图片保存、目录约束和伪造内容拒绝。

业务前端和管理后台均有生产构建脚本，但仓库内尚未建立组件测试或端到端测试套件。

## 八、优先待办

1. 实现 `PPDVedge` 通信、安全和底盘最小闭环，并与当前 MQTT 协议联调。
2. 将作业规划升级为可持久化的航线、任务和进度模型，并接入车端执行回执。
3. 接入真实视觉识别服务，并定义模型版本、置信度阈值和人工复核流程。
4. 补齐告警确认/通知、OTA、视频流和对象存储能力。
5. 增加区域生命周期、权限矩阵、风险规则边界和业务闭环的接口集成测试。
6. 为业务前端增加组件测试与端到端测试。

## 九、维护规则

- 新增或删除模块时，同一 PR 必须更新本文件。
- 状态升级为“已完成”前，应同时存在主要实现、可用入口和至少一种验证方式。
- 只有接口或数据库表而没有用户入口时，默认标为“部分完成”。
- `PPDVedge` 只有说明文件时不得标为“已完成”。
- 规划发生变化时同步更新 [architecture.md](architecture.md)；接口或 MQTT 消息变化时同步更新 [protocol.md](protocol.md)。
