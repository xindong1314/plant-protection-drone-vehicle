# 植保无人车软件系统 · 架构与模块设计

## 概述

本系统面向**植保无人车**（自主/远程作业的地面喷洒机器人）的完整软件栈。系统在物理上分为两大部分：

- **车载端（嵌入式实时控制）**：运行在无人车上的工控机 / 嵌入式板卡，负责感知、定位、导航、运动与喷洒控制、安全防护，强实时性。对应目录 `PPDVedge/`。
- **云端 Web 系统**：设备管理、任务调度、监控与数据分析的服务端与前端。对应目录 `PPDVapi/`、`PPDVweb/`、`PPDVadmin/`。

两部分通过 MQTT / 4G-5G 交换遥测数据与控制指令。

## 技术栈

| 层 | 目录 | 技术栈 |
|----|------|--------|
| 车载端 | `PPDVedge/` | **ROS2**（C++ / Python 节点） |
| 云平台后端 | `PPDVapi/` | **Spring Boot**（Java） |
| 业务前端 | `PPDVweb/` | **Vue** |
| 管理后台前端 | `PPDVadmin/` | **Vue** |

配套中间件：MQTT Broker（车云通信）、消息队列、时序数据库、关系数据库、Redis、对象存储（详见"贯穿各层的技术支撑"）。

## 一、车载端（PPDVedge）

决定"车能不能自己跑起来、喷得准不准"，是整个植保作业的核心，技术难度最高。运行在车上，强实时。

| 模块 | 职责 | 关键点 |
|------|------|--------|
| 环境感知 (perception) | 传感器采集与融合 | 摄像头、激光雷达、毫米波/超声波雷达、RTK-GPS、IMU；障碍物检测、作物行识别 |
| 定位导航 (navigation) | 定位与路径 | RTK 厘米级定位 + SLAM；全局路径规划（往复式/回字形覆盖）+ 局部避障 + 路径跟踪（纯追踪/MPC） |
| 运动控制 (control) | 底盘运动闭环 | 驱动、转向、速度闭环；阿克曼或差速运动模型 |
| 喷洒作业控制 (spray) | 喷洒执行 | 喷头开关、流量/压力调节、变量喷洒（按处方图调药量）、药箱液位、风幕 |
| 安全防护 (safety) | 保护与容错 | 急停、电子围栏越界保护、碰撞保护、低电量返航、看门狗、故障诊断。优先级最高，须独立 |
| 通信上报 (comm) | 与云端通信 | 4G/5G/LoRa + MQTT 上报位置/状态/作业数据，接收远程指令 |

## 二、云平台 / 后端（PPDVapi）

设备接入后的管理与调度层。

| 模块 | 职责 |
|------|------|
| 物联接入 (IoT 网关) | 设备接入、协议适配、消息队列（MQTT Broker + Kafka/RabbitMQ），遥测落时序库 |
| 设备管理 | 车辆注册、在线状态、固件 OTA 升级、设备影子 |
| 任务调度 | 作业任务下发、进度跟踪、断点续喷记录 |
| 地图航线 | 农田地块 GIS、电子围栏、AB 线/航线规划、处方图 |
| 实时监控 | 位置/状态遥测、视频流转发 |
| 数据统计 | 作业面积、用药量、作业质量、报表 |
| 告警通知 | 故障/越界告警、消息推送 |
| 用户权限 | 用户/角色/组织、RBAC、多租户 |

## 三、应用端 / 前端（PPDVweb + PPDVadmin）

| 子系统 | 职责 |
|--------|------|
| PPDVweb（业务前端） | 监控大屏/驾驶舱、地图作业规划（画航线/圈地块）、实时车辆监控、报表 |
| PPDVadmin（管理后台） | 用户权限、设备台账、系统配置、字典/药剂库等基础数据维护 |

## 贯穿各层的技术支撑

不属于某个业务模块，但各层都会用到：

- **消息队列**：MQTT / Kafka —— 设备接入与异步解耦
- **时序数据库**：InfluxDB / TDengine —— 存海量遥测数据
- **关系数据库**：业务数据
- **缓存**：Redis
- **对象存储**：视频 / 图片
- **日志与监控**：可观测性

## 演进建议

1. **优先级**：车载端（尤其定位导航 + 安全防护）决定成败，建议尽早立项；Web 系统先跑通"设备管理 + 实时监控 + 任务下发"主线。
2. **技术栈**：已确定 —— 后端 Spring Boot、前端 Vue、车载端 ROS2（见上方「技术栈」节）。
3. **接口约定**：车载端与云端的 MQTT Topic、消息格式（遥测/指令）见 [protocol.md](protocol.md)（草案 v0.1，待评审冻结）。
